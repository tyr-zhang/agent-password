# 本地化（i18n）

语言：[English](i18n.md) · [简体中文](i18n.zh-CN.md)

agent-pwd 只翻译面向人的 CLI 文本。任何供程序、脚本或代理解析的内容都属于稳定的机器契约，必须保持英文。

## 支持的语言与选择方式

| 代码 | 语言 |
|---|---|
| `en` | 英语——规范源语言与回退语言 |
| `zh-CN` | 简体中文 |

选择优先级如下：

1. `--lang <code>`（全局标志，命令前后均可，但 `--` 之后不生效）
2. 环境变量 `AGENT_PWD_LANG`
3. `en`

示例：

```bash
agent-pwd --lang zh-CN status
AGENT_PWD_LANG=zh-CN agent-pwd docs
```

`--lang` 也支持 `--lang=<code>` 写法。输入会去除首尾空白并忽略大小写；别名 `zh`、`zh-cn`、`zh_cn`、`zh-hans`、`zh_hans` 会映射到 `zh-CN`。不支持的值回退到 `en`。系统区域设置永远不会被读取，因此生成结果是确定的。`make docs` 在生成两个契约文件时会显式设置 `AGENT_PWD_LANG=en` 与 `AGENT_PWD_LANG=zh-CN`。

## 规范的英文键

翻译层位于 [`internal/i18n/i18n.go`](../internal/i18n/i18n.go)，目录位于 [`internal/i18n/catalog.go`](../internal/i18n/catalog.go)。

- 每次调用 `i18n.T(lang, key, args...)` 时，**键就是精确的英文原文字符串**。英文是同一语言：`T(en, key)` 原样返回 `key`。
- `catalogZHCN` 把这些规范英文键映射到简体中文。缺少某个键时，输出回退为英文键而不是报错。
- 命令摘要、[`internal/cli/docs.go`](../internal/cli/docs.go) 中的契约章节，以及人可读的 CLI 消息都是键。修改英文措辞会创建*新*键，因此需要在同一改动中更新目录。
- 格式参数通过 `fmt.Sprintf` 展开，因此键中的占位符是其身份的一部分，必须与调用处一致。

## 翻译规则

1. **占位符一致。** 保留英文键中的每个 `%s`、`%d`、`%q`、`%%` 及其他格式动词：数量、顺序和类型都要相同。不要新增、删除或重排占位符，否则运行时输出会出错。
2. **反引号一致。** 反引号在 Markdown 和 CLI 文本中标出内联代码。保留相同数量的反引号片段及其内容，包括命令、标志、路径和字面值。不要翻译反引号内的文字。
3. **标志一致。** 命令名、子命令、标志名、标志值、`<占位符>` 与示例（例如 `agent-pwd docs`、`--lang zh-CN`、`confirm approve <id>`、`--format md|json`）保持原样，只翻译外围的说明文字。
4. **语义与语气。** 精确对应英文含义，保持消息简洁；不要引入英文中没有的承诺、行为或安全保证。不确定时保留英文原文。

## 不得翻译的机器 token

- **JSON 键与字段名：** `ok`、`error`、`code`、`message`、`result`、`status`、`version`、`commands`、`exit_codes`、`contract`、`confirmation_id`、`poll_token` 等字段。
- **枚举与字面值：** `allow`、`confirm`、`deny`、`normal`、`high`、`md`、`json`、`en`、`zh-CN`，以及 decision/outcome/result-code 等字面常量。
- **退出码：** `0`、`10`、`20`、`30`、`40`、`1` 及其作为机器值的既定含义。
- **错误码：** `OK`、`PENDING`、`LOCKED`、`NO_DAEMON`、`DENIED`、`NOT_FOUND`、`BAD_ARGS`、`EXISTS`、`CORRUPT`、`TIMEOUT`、`BIOMETRIC_REQUIRED`、`INTERNAL`。
- **命令与标志名：** 注册表中的所有命令或子命令，`--cred`、`--token`、`--human`、`--json`、`--lang`、`--format`，以及所有以 `--` 开头的选项。
- **审计字段：** `seq`、`ts`、`credential_id`、`action`、`decision`、`confirm_source`、`outcome`、`result_code`、`detail_hash`、`policy_rule`、`client`、`prev_hash`、`hash`。
- **诊断信息：** 面向机器的标识符、错误码字符串、日志字段名，以及消息中用于匹配或工具解析的稳定 token 均保持英文。只有其周围供人阅读的叙述可以通过 `T()` 翻译。

秘密、哈希、凭据 ID、token、文件名和平台路径同样不得翻译。

## 如何新增一种语言

新增语言是代码改动，而不只是目录改动：

1. 选择一个语言代码（使用类似 `fr` 的 BCP-47 风格代码），并在上表和面向贡献者的文档中登记。
2. 在 [`internal/i18n/i18n.go`](../internal/i18n/i18n.go) 中新增 `Lang` 常量，在 `ParseLang` 中加入可接受的别名，并把该代码加入 `Supported()`。
3. 在 [`internal/i18n/catalog.go`](../internal/i18n/catalog.go) 中新增 `catalogXX` 映射，并扩展 `T()` 以选择它。保持 `en` 为同一语言回退；不要加入系统区域检测。
4. 枚举当前所有 `i18n.T` 键，为新目录补齐译文。缺少的键会回退英文；建议用测试或覆盖率检查发现遗漏。
5. 更新 `--lang` 的帮助文本，以及所有列举支持语言的说明文字。
6. 如果生成的 AI 契约需要包含新语言，请扩展 [`Makefile`](../Makefile) 中的 `docs` 与 `docs-check` 目标，使其生成并比对 `docs/contract.<code>.md`。
7. 在 `internal/i18n` 和 `internal/cli` 中添加解析、回退、占位符与生成文档方面的测试。

## 常用命令

```bash
make i18n-check   # go test ./internal/i18n ./internal/cli
make docs         # 重新生成 docs/contract.md 与 docs/contract.zh-CN.md
make docs-check   # 若生成的契约文件不同步则失败
make test         # 完整单元测试、集成测试与安全回归测试
make vet
make race
make cross
```

`make docs-check` 会把新生成的契约文件写入 `/tmp` 并与仓库中的文件做 diff。翻译或命令接口发生改动时，请连同重新生成的文档一起提交。
